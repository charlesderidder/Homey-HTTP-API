    API gebruiken

    Gebruik de triggerkaart in Advanced Flow om een route en HTTP-methode te registreren.

    Voorbeeld van een route

    /informatie

    De slash aan het begin is optioneel. informatie en /informatie verwijzen naar dezelfde route.

    HTTP-methoden

    GET, POST, PUT, PATCH, DELETE, HEAD en OPTIONS

    Gebruik POST, PUT en PATCH voor JSON-data. Gebruik GET om data op te vragen en DELETE om een actie of resource te verwijderen.

    Antwoord vanuit Flow

    Gebruik de actiekaart Reageer met... om een JSON-antwoord terug te sturen, of Reageer met 200 voor een eenvoudige bevestiging.

    Een enkele waarde opvragen

    Voeg ?veld= toe aan een GET-request om een enkele eigenschap uit het Flow-antwoord op te vragen. field= is ook mogelijk. De eigenschap mag rechtstreeks in het antwoord of binnen data staan.

    GET /alles?veld=Zonsopkomst
    API authentication
    Use in the URL: /informatie?token=abc

    How the API settings work

    Configure the local HTTP server here. Changes take effect after saving and restarting the app if Homey indicates that a restart is required.

    Server settings

    Port determines where the API listens. CORS controls whether browser-based clients may make cross-origin requests. Access-Control-Allow-Origin limits which origin is allowed when CORS is enabled.

    Routes and methods

    Create a trigger flow with a route such as informatie and select its HTTP method. A leading slash is optional, so informatie and /informatie are equivalent.

    Supported methods are GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS. POST, PUT, and PATCH can receive JSON in the request body.

    API token

    Enable token authentication and generate a token. The recommended format is the Authorization header. For simple URL clients, add the token as shown below.

    /informatie?token=abc

    The token is checked before a Homey flow starts. Generating a new token invalidates the old token. Do not share the token or expose the API port directly to the public internet.

    Request examples

    Register the route and method in an Advanced Flow trigger, then use one of these requests from a client or HomeyScript.

    GET

    Read the current status.

    GET /informatie?token=abc

    Read a specific room value.

    GET /woonkamer/temperatuur?token=abc

    Read all available data.

    GET /alles?token=abc

    Read a single value from the response.

    GET /alles?veld=Zonsopkomst&token=abc

    POST

    Create a new item.

    POST /apparaat
{"name":"lamp woonkamer","type":"light"}

    Start a scene.

    POST /scene/avond
{"brightness":40}

    Send an event to Homey.

    POST /event
{"event":"deur geopend","source":"sensor"}

    PUT

    Replace a complete device configuration.

    PUT /apparaat/woonkamer
{"enabled":true,"brightness":80}

    Replace a complete schedule.

    PUT /schema/avond
{"start":"20:00","action":"on"}

    Set a complete thermostat state.

    PUT /thermostaat
{"target":21,"mode":"heat"}

    PATCH

    Change only the brightness.

    PATCH /apparaat/woonkamer
{"brightness":50}

    Change only the target temperature.

    PATCH /thermostaat
{"target":20}

    Change only the enabled state.

    PATCH /apparaat/woonkamer
{"enabled":false}

    DELETE

    Remove a saved device.

    DELETE /apparaat/test

    Remove a schedule.

    DELETE /schema/avond

    Clear a temporary value.

    DELETE /waarde/tijdelijk

    HEAD

    Check whether an endpoint is available without downloading its response.

    HEAD /informatie

    Check whether a device endpoint exists.

    HEAD /apparaat/woonkamer

    Check whether the API is reachable.

    HEAD /status

    OPTIONS

    Ask which HTTP methods are available for a route.

    OPTIONS /informatie

    Check the CORS preflight response.

    OPTIONS /apparaat

    Inspect the allowed methods before integrating a client.

    OPTIONS /api

    When authentication is enabled, add ?token=abc to the URL or use Authorization: Bearer abc. POST, PUT, and PATCH bodies must contain valid JSON.
